## ISSUE-003 — Date picker crashed the entire dashboard (CRITICAL)

**Severity:** Critical | **Category:** Functional | **Status:** fixed, verified
**Commit:** `bf8e23f` + regression test `03d1497`
**Files:** `app/streamlit_app.py`, `app/data.py`, `tests/test_date_range.py`

`st.date_input` in range mode returns a **1-tuple** between the first and second
click. The code unpacked it straight into two names:

```python
date_from, date_to = st.date_input(...)   # unpack happens HERE
if isinstance(date_from, tuple):          # guard sat AFTER — never ran
```

**Repro:** load the page, click the date range box, click any single day.

**Result:** every chart replaced by
`ValueError: not enough values to unpack (expected 2, got 1)`.
Evidence: `screenshots/issue-003-single-date.png`.

This fired on the first click of the **only filter in the app**, so any visitor
who touched the date control destroyed the page.

**Fix:** normalisation extracted to `data.normalize_date_range()` and applied
*before* unpacking. Handles two dates, one date (collapses to that day), cleared,
and a bare date object.

**Verification:** the browser harness could not re-drive Streamlit's calendar
portal reliably, so re-verification is by regression test rather than by click.
12 tests pass, and the old line was confirmed to still raise the exact
`ValueError` when simulated. Page is healthy: 9 charts, no traceback.

## ISSUE-002 — Header stated a date range the data does not have (HIGH)

**Severity:** High | **Category:** Content | **Status:** fixed, verified
**Commit:** `34eeeed` | **Files:** `app/data.py`, `app/streamlit_app.py`

The header read *"Snapshot: data through 2026-06-11"* while the shipped Parquet
ends **2025-12-31** and every chart stopped in 2025. `DATA_THROUGH` described the
**source** dataset, not the 2019-2025 slice actually shipped.

**Evidence:** date picker showed `2019/01/01 – 2025/12/31`; Parquet bounds
confirmed `(2019-01-01, 2025-12-31, 812315)`.

**Fix:** renamed to `UPSTREAM_THROUGH`, and coverage is now derived from the
selected range (`date_from`/`date_to`), so it cannot drift from what is on
screen and stays correct when the filter moves.

## ISSUE-001 — Headline contradicted the KPI beneath it (MEDIUM)

**Severity:** Medium | **Category:** UX | **Status:** fixed, verified
**Commit:** `34eeeed` | **Files:** `app/streamlit_app.py`

Title said **40%**; the KPI directly below said **44.2%**, with nothing
reconciling them. Both are correct (40% is the full 2012-2026 table, 44.2% is
2019-2025) but a visitor sees two numbers for one claim and trusts neither. On a
project whose entire thesis is numeric honesty, this is the worst possible place
for an unexplained discrepancy.

**Fix:** one reconciliation line under the header, and the KPI relabelled
"Deaths in unlabeled rows, this range".
